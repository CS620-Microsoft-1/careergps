## 3. 实际执行流程与分工

| 步骤 | 执行方 | 处理内容 |
|---|---|---|
| 1 | Python | 校验输入，筛选岗位，排除重复、高级及其他不符合范围的记录 |
| 2 | Agent | 从每条 JD 提取技能、原文引用，区分必需、加分、背景提及和明确不要求 |
| 3 | Python | 校验引用，逐岗位去重，计算每项技能的需求比例 |
| 4 | Agent | 从确认后的简历提取技能证据，返回原文、字段路径和证据类别 |
| 5 | Python | 校验证据来源，把类别映射为证据分数，再计算缺口和排序 |
| 6 | Agent | 解释已有结果，给出行动建议和完成后应提供的证明材料 |
| 7 | Python | 校验最终技能列表、顺序、分数和优先级，保存报告 |

三次 Agent 调用使用同一个已配置的 Skill Gap Agent，通过不同任务名称和输出 JSON Schema 区分职责。

当前 [Agent Prompt](</D:/cs620 proj/docs/skill-gap-agent-prompt.md>) 支持 `extract_job_requirements`、`extract_resume_evidence`、`explain_skill_gaps` 三种任务。用户更新了 Azure Instructions；程序仍会在每次请求中发送本地 Prompt，因此测试验证的是两者共同作用下的完整调用流程。

## 4. 计算方法

### 4.1 简历证据分数

| 证据情况 | Python 分数 | 含义 |
|---|---:|---|
| 未提取到证据 | 0 | 当前简历没有被识别出的支持内容，不代表用户不会 |
| `listed` | 0.25 | 仅列出技能、技术栈或课程 |
| `applied` | 0.60 | 明确描述使用该技能完成具体任务 |
| `validated` | 0.80 | 明确描述与该技能相关的测试、测量或验证活动 |
| 两个独立条目的验证证据 | 1.00 | 当前规则下的充分证据；独立性判断仍有待修复的问题，见第 7 节 |

Agent 只返回类别和引用，不直接填写分数。引用必须能在对应 JSON 路径的原始字符串中找到，并明确包含该技能或已配置的别名。

这些分数衡量简历证据覆盖情况，不是经过测验的技能熟练度。简历中写了测试经历，也不表示本流程实际运行或核实了那些测试。

### 4.2 岗位需求比例

```text
需求比例 = 提出该技能要求的去重岗位数 ÷ 筛选后的有效岗位总数
```

当前“提出要求”包含必需和加分项，每个岗位对同一技能最多计数一次。公司背景提及和明确不要求的技能不计入。必需数量与加分项数量也会分别保存。

SQL 和 PostgreSQL 分开统计；程序不会仅因 JD 提到 PostgreSQL，就自动推断其明确提出 SQL 要求。

### 4.3 缺口分数与优先级

```text
缺口分数 = 岗位需求比例 ×（1 − 简历证据分数）
```

分数保留六位小数，按降序排列。暂定分档为：高优先级 ≥ 0.60；中优先级 ≥ 0.30 且 < 0.60；低优先级 < 0.30。

这是用于安排证据补充工作的实验性指标，不是能力缺失百分比、职位匹配率或录用概率。权重和阈值尚未通过人工标注数据校准。

在用户更新 Azure Instructions 后，三阶段真实 Agent 调用成功，耗时 **61.415 秒**。7 条原始招聘记录筛选为 **5 个有效岗位、4 家模拟公司**。

| 技能 | 必需岗位数 | 仅加分岗位数 | 合并需求比例 | 简历证据分 | 缺口分 | 优先级 |
|---|---:|---:|---:|---:|---:|---|

## 6. 如何理解最后的建议

**Docker：优先补充项目证据。** 简历没有相关内容，可以给已有 FastAPI 项目增加 Dockerfile、运行说明和可复现演示。但样本中只有 1/5 的岗位把它列为必需，3/5 将其列为加分项，不能把合并的 80% 解读为普遍硬性门槛。

**PostgreSQL、SQL：补充实际应用。** 当前只展示技能名称或课程。可以在同一个项目中展示数据库设计、查询、迁移和测试，同时补充两类证据，无需机械地安排两个独立项目。

**Git：完善已有协作证据。** 已经有分支和 PR 使用经历，中优先级表示可以更完整地展示真实协作过程和成果，不表示用户不会 Git。新增演示必须标明是演示，不能伪造过去的项目或协作历史。

**Python、JavaScript、React：优先保留和完善已有成果。** 当前简历已经描述了项目应用，其中 Python 还描述了测试活动。建议补充真实代码、运行说明和演示，而不是据此要求用户从零学习。

以上解释仅针对这组模拟内容，不能作为对真实用户能力或真实就业市场的判断。

## 7. 已验证内容与尚存问题

已有测试记录显示 **33 项 Skill Gap 专项测试通过**，覆盖输入结构、岗位筛选、去重、统计分母、原文引用、别名、证据映射、无效输出拒绝及数据库隔离。最近一次真实 Agent 输出也通过了数值、技能顺序和优先级校验。

尚待完善的问题如下，均未在本次文档工作中修改：

1. **重复证据可能抬高分数。** 已通过只读复现确认：把同一句验证经历复制到两个不同条目，当前代码可能将其视为独立证据，把 0.80 提升至 1.00。需要增加内容去重和独立性检查。
2. **必需与加分项同等参与排名。** 数学统计正确，但可能放大可选技能的优先级。应先保留区别，再评估权重。
3. **最后总结缺少完整需求明细。** 最终 Agent 输入目前主要包含合并比例，未包含完整的必需／加分项数量；明细虽已保存，尚未全部传入总结阶段。
4. **引用校验不保证分类准确或提取完整。** Agent 可能漏掉证据或误判类别，需要人工标注样本评估，而不能只检查 JSON 是否合法。
5. **评分与阈值未校准。** 当前分数表示规则下的证据覆盖，未评估岗位所需的实际能力深度。固定阈值也可能忽略出现率较低但对某个岗位很关键的技能。
6. **样本与筛选范围有限。** 当前只有 5 个模拟岗位，且混合前端、后端、平台和全栈方向。程序已标记低置信度。保守的标题、国家和日期筛选也可能排除真实有效岗位。

建议优先顺序：修复重复证据加分 → 将需求明细传入总结 → 完善行动建议合并 → 用人工标注样本校准评分与提取质量。
